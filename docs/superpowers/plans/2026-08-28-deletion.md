# Deletion (Entries, Folders, Tasks, Projects) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let both the dashboard (human) and MCP tools (agent) permanently delete a memory entry, a folder, a whole task, or a whole project - the one deliberate exception to this app's "dashboard is read-only" rule.

**Architecture:** Every cascade (task → its entries/folders/agent-task board; folder → subfolders; folder deletion → un-filing its direct entries, not deleting them) is already enforced by `ON DELETE CASCADE`/`ON DELETE SET NULL` foreign keys declared back in migrations V1-V8 - verified by reading every migration, not assumed. So `FolderService.delete`/`TaskService.delete` are each a single-row JPA delete; only project-level delete (a project is a derived `projectScope` value, not a real row) touches multiple tables itself. `MemoryService.delete` and the `memory_delete` MCP tool already exist and need no backend changes - only a REST wrapper.

**Tech Stack:** Same as the rest of the codebase - Java 25 / Spring Boot / Spring Data JPA / PostgreSQL (backend); Vue 3 + TypeScript (frontend); no new dependencies.

**Spec:** `docs/superpowers/specs/2026-08-28-deletion-design.md`

## Global Constraints

- No new FK/migration work - Task 1 only adds repository methods, the schema already cascades
  correctly (verified against V1-V8; do not add a new migration for this plan).
- Every new REST delete endpoint reuses an **existing** exception class
  (`MemoryNotFoundException`, `FolderNotFoundException`, `TaskNotFoundException` - all already
  registered in `ApiExceptionHandler` as 404) - do not create new exception types for this plan.
- `ProjectService.delete(projectScope)` is idempotent and never throws "not found" - a project is
  a derived scope, not a row, so deleting an empty/nonexistent one is a silent no-op, not an
  error.
- Delete lives on **detail pages only** (`EntryView.vue`, `FolderView.vue`, `TaskView.vue`,
  `ProjectView.vue`) - do not add delete affordances to the list-card components
  (`EntryCard`/`FolderCard`/`TaskCard`/`ProjectCard`), which are each a single `RouterLink`
  wrapping the whole card; nesting an interactive delete button inside would reintroduce the
  click-bubbling bug already hit and fixed once this session on `AgentTaskCard`.
- Confirm dialogs state cascade impact using counts already loaded on that page (`entries.length`,
  `folders.length`, `agentTasks.length`, `tasks.length`) - no new backend "preview" endpoint.
- `project_delete`'s `@McpTool` description must instruct the agent to always get explicit user
  confirmation before calling it, matching the existing convention (`task_start`'s "ALWAYS ask the
  user explicitly").
- Backend tests: `@SpringBootTest @Transactional`, AssertJ, real Postgres, matching
  `FolderServiceTest`/`AgentTaskServiceTest` conventions. Controller tests:
  `@ExtendWith(MockitoExtension.class)` + `MockMvcBuilders.standaloneSetup(...)
  .setControllerAdvice(new ApiExceptionHandler())`, matching `FolderViewControllerTest`.
- Frontend: no automated test harness in `ui/` - verify via `npm run type-check`.

```java
        node.setProjectScope("task-cascade-test-project");
        node.setTask(savedTask);
        node.setCreatedAt(now);
        node.setUpdatedAt(now);
        MemoryNode savedNode = nodeRepository.saveAndFlush(node);

        Folder folder = new Folder();
        folder.setName("task-cascade-test-folder");
        folder.setDescription("desc");
        folder.setProjectScope("task-cascade-test-project");
```

```java
package ru.iuribabalin.memorymcp.service;

import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import ru.iuribabalin.memorymcp.dto.ProjectSummary;
import ru.iuribabalin.memorymcp.repository.FolderRepository;
import ru.iuribabalin.memorymcp.repository.MemoryNodeRepository;
import ru.iuribabalin.memorymcp.repository.TaskRepository;
import ru.iuribabalin.memorymcp.repository.UsageEventRepository;

import java.util.List;

@Service
public class ProjectService {

    private final MemoryNodeRepository nodeRepository;
    private final TaskRepository taskRepository;
    private final FolderRepository folderRepository;
    private final UsageEventRepository usageEventRepository;

    public ProjectService(MemoryNodeRepository nodeRepository, TaskRepository taskRepository,
                           FolderRepository folderRepository, UsageEventRepository usageEventRepository) {
        this.nodeRepository = nodeRepository;
        this.taskRepository = taskRepository;
        this.folderRepository = folderRepository;
        this.usageEventRepository = usageEventRepository;
    }

    @Transactional(readOnly = true)
    public List<ProjectSummary> list() {
        return nodeRepository.findAllProjectScopes().stream()
                .distinct()
                .sorted()
                .map(scope -> new ProjectSummary(
                        scope,
                        nodeRepository.countByProjectScopeAndTaskIsNull(scope),
                        taskRepository.countByProjectScope(scope)))
                .toList();
    }

    /**
     * A project is a derived projectScope value, not a row - deletes every Task with this scope
     * first (cascades away everything scoped to each one), then whatever common-scope (task-less)
     * data is left, then usage-event history. Idempotent: an empty/nonexistent scope is a no-op,
     * not an error.
     */
    @Transactional
    public void delete(String projectScope) {
        taskRepository.deleteByProjectScope(projectScope);
        nodeRepository.deleteByProjectScopeAndTaskIsNull(projectScope);
        folderRepository.deleteByProjectScopeAndTaskIsNull(projectScope);
        usageEventRepository.deleteByProjectScope(projectScope);
    }
}
```

```ts
async function deleteRequest(path: string): Promise<void> {
  let response: Response
  try {
    response = await fetch(path, { method: 'DELETE' })

    throw new ApiError(response.status, message)
```
